## 1. 확인한 사실

출처는 nmemo 저장소 기준.

- 보드는 순수 DOM + framer-motion. `.board > .world` 하나에 `translate3d+scale`을 직접 써서 이동/확대(`src/ui/viewport.ts:40`), React 재렌더 없음. 확대 0.3–2.4.
- 메모 1개 = 중첩 div 5~6개(`src/ui/MemoCard.tsx:92-158`). 주제 무리 = blur 방사형 그라데이션 div + 라벨(`src/ui/Board.tsx:32`). 관련 곡선만 SVG(`RelatedLines`).
- 위치는 저장하지 않고 매번 계산: `src/core/layout/clusters.ts` d3-force 두 단계 — 무리 안 카드 배치(80-95행), 무리끼리 배치(141-160행, 주제 간 링크 합이 당기는 힘). 출력은 2D 월드 좌표 `{clusters{x,y,r}, cards{x,y,topicId}}`.
- 2D 좌표에 묶인 것: 저장 시 포물선 비행(`FlightCard`, `Board.tsx:96`, 월드→화면 변환 `v.x+pos.x*v.k`), 재구성 이동 호, 착지 출렁임, 관련 곡선, 끌어 놓기 판정 `clusterAt`(중심 거리 < r), 무리 열기(확대+1.6배 펼침), 첫 화면 맞춤, `overview-btn`.
- 입력: 하단 `.dock`에 쓰기·녹음·사진 3버튼(`src/ui/InputBar`, `App.tsx:147-150`). 쓰기를 눌러야 textarea가 열림. 녹음은 누르고 있는 동안 Web Speech. 저장은 즉시 pending → 대기열이 정돈하면 pending 카드 위치에서 목표 무리로 비행(`App.tsx:54-64`).
- 데모 40메모·6주제. 설계 목표: 중급 안드로이드에서 카드 200장 근처 60fps(`docs/DESIGN.md` §7·§8). 카드 위치는 transform만 애니메이션.
- `src/core/`는 React·DOM·브라우저 전역 금지(ESLint로 강제, RN 이전 대비 §8.1). 새 배치 수학도 여기 순수 함수로 둬야 함.
- e2e(`tests/e2e/smoke.spec.ts`)가 평면 보드에 강하게 묶임: `.cluster-label` 좌표로 클릭·드롭, `overview-btn`, `btn-write/voice/photo`, `[data-memo-id]` 클릭, `flight-card` 사라짐 등.
- 이 저장소에는 아직 `CLAUDE.md`·`STATUS.md`·`docs/decisions.md`가 없다(결정 기록은 `docs/DESIGN.md` §11).

가정:
- 사용자의 "지구본"은 물리적으로 정확한 구가 아니라 **회전하는 느낌**이다. 375px 폰에서 정면 주제가 메모를 다 보여 주려면 무리 하나가 화면 폭 대부분을 차지해야 하므로, 정확한 구 투영으로는 불가능하다(정면 무리 지름 ≈ 지구본 지름).
- 주제 수는 당분간 5~20개, 메모 수백 개 이하.

## 2. 도구 비교 (객관 평가)

| 방식 | 무엇 | 장점 | 단점 | 이 앱에 |

## 3. 설계

### 3.1 배치 (`src/core/layout/globe.ts`, 순수 함수)

- 주제마다 경도 λ와 위도 β를 정한다.
  - λ: 주제 순서를 원 위에 고르게. 순서는 주제 간 링크가 강한 것끼리 이웃하도록(지금 무리끼리 당기는 힘을 1차원 원 순서로 바꿈). 새 주제가 생겨도 기존 순서는 최대한 유지(이전 결과를 시작점으로).
  - β: -30°~+30° 사이, 이웃끼리 높이가 다르게(해시 + 교대). "한 줄이 아닌 여러 높이".
- 무리 안 카드 배치는 지금 d3-force 카드 단계를 그대로 쓴다(무리 로컬 좌표).
- 투영 `project(λ, β, φ)` → `{x, y, scale, opacity, z, side}`:
  - Δ = λ − φ (−180°~180°로 접음). 깊이 z = cos Δ.
  - x = 화면중심 + Rx·sin Δ, y = 화면중심 − Ry·sin β·(0.6+0.4z). 정면에서 위아래 폭이 가장 넓고 옆으로 갈수록 적도로 모임(구 느낌).
  - 크기: 정면 1.0, |Δ|=60° 약 0.45, 뒷면 0.3. 정확한 구가 아니라 곡선으로 조절(가정 참조).
  - 투명도: 정면 1, 옆 0.55, 뒷면 0.15. 뒷면은 좌우가 뒤집혀 반대 방향으로 흐른다(지구본 뒤쪽이 비치는 느낌).
  - 겹침 순서는 z.
- 모든 값은 상수 묶음 하나로 두어 프로토타입에서 손으로 조절.

### 3.2 회전 (`src/ui/globe/`)

- 좌우 끌기 = φ 변경. 손 뗄 때 속도로 관성 → 가장 가까운 주제가 정면에 오도록 스프링으로 멈춤(스냅). 데스크톱은 휠(가로·세로 모두)과 끌기.
- 프레임마다 무리 수(N)만큼만 transform을 직접 씀(React 재렌더 없음). 카드는 무리 컨테이너 안에 있어 카드별 계산 없음 → 200장이어도 비용은 주제 수에 비례.
- 정면 무리(|Δ|<20°): 카드 전부, 원래 크기, 글자 읽힘. 세로로 넘치면 무리 안에서 위아래 스크롤.
- 옆 무리: 카드 전부를 작게(스케일만). 주제 15개 이상이면 |Δ|>90° 무리는 라벨+점 구름으로 단순화(세부 단계 LOD).
- 두 손가락 오므리기 → 지구본 전체를 작게(모든 주제 라벨이 보이는 조망), 라벨 탭 → 그 주제로 회전. 지금 `overview-btn` 역할.
- 반투명: 투명도와 크기만 사용. blur 필터는 무리 배경 glow에만(이미 있음).
- 멈춘 뒤 정면 무리는 scale 1로 다시 그려 글자를 선명하게.
- 제스처 판정: 처음 8px 움직임의 방향으로 축을 고정(가로 = 회전, 세로 = 정면 무리 스크롤). 보드에 `touch-action: none`, iOS `gesturestart` 기본 동작 막기, 화면 왼쪽 가장자리 20px는 비워 뒤로가기 스와이프와 겹치지 않게.
- 각도 간격: 주제 간 간격은 최소 30°, 최대 72°. 주제가 12개를 넘으면 위도를 두 줄 이상으로 나눠 같은 경도에 둘 수 있게(간격 유지). 주제 1~2개면 정면과 ±간격에 둔다(뒷면에 두지 않음).
- 큰 주제(옆에서 카드 30장 초과): 옆에서는 대표 카드 몇 장 + "+N"으로 요약.

### 3.3 기존 동작 옮기기

- 저장 비행: 목표 주제가 옆·뒤에 있으면 먼저 지구본을 돌려 정면에 오게 하고 → 그 위로 착지. 착지 지점은 투영된 화면 좌표.
- 끌어 놓기: 카드를 들고 화면 좌우 가장자리에 머물면 지구본이 천천히 돈다 → 다른 주제 라벨 위에 놓기. 판정은 투영 좌표 기준.
- 관련 곡선: 정면 무리 안 카드끼리만 그림. 다른 주제로 이어지는 링크는 그 방향 가장자리에 작은 표시.
- 무리 열기·이름 바꾸기: 정면 무리 라벨 탭 → 지금처럼 `ClusterBar`.
- 재구성 이동: 정면 무리 안이면 호를 그리며 이동, 다른 주제로 가면 페이드 아웃→인.
- 동작 줄이기 설정: 관성·자동회전 없음, 스냅은 즉시, 뒷면 숨김.

### 3.4 바로 쓰기 (`App`, 새 `Composer`)

- 앱을 켜면(또는 5분 이상 지나 다시 열면) **쓰기 모드**: 화면 정면에 큰 쓰기 칸, 뒤에 지구본이 흐리게(보드 층 전체에 opacity 0.4 + blur 6px, 쓰기 모드 동안만) 천천히 돈다.
- 쓰기 칸에 자동 포커스. **한계: iOS 사파리·iOS 홈화면 앱은 사용자 제스처 없이 `focus()`를 무시해 키보드를 띄우지 않는다.** 그래서 iOS에서는 깜빡이는 가짜 커서를 그려 두고 한 번 탭하게 한다(구조상 0단계 불가). 안드로이드도 PWA를 다시 열 때는 키보드가 안 뜨는 경우가 많아 실기기 검증이 필요하다. 데스크톱은 첫 키 입력이 바로 쓰기 칸으로 간다.
- 키보드가 뜨면 `visualViewport` 기준으로 쓰기 칸 위치를 잡고, 뒤 지구본의 투영 중심은 키보드가 뜨기 전 값으로 고정해 튀지 않게 한다.
- 연달아 저장할 때 배경 회전은 합친다: 1.5초 안의 저장들은 마지막 목표 주제로 한 번만 돈다. 분류가 끝나기 전에는 돌지 않는다.
- 쓰기 칸 안 오른쪽 아래 `+` 하나 → [녹음] [사진] 펼침(D5).
- Enter 저장 → 글이 카드가 되어 뒤 지구본으로 날아감(지구본은 그 주제 쪽으로 돌아감). 쓰기 칸은 비워진 채 유지(D6).
- 아래로 쓸어내리기 / 흐린 보드 탭 → 보드 모드(흐림이 걷히고 지구본 조작). 보드 모드에서는 화면 아래에 작은 펜 버튼 하나 → 탭하면 쓰기 모드.
- 기존 하단 3버튼 바와 pending 트레이는 없앰. 대기 중 메모는 쓰기 칸 위에 작은 칩으로.

## 4. 종료 조건 (실행 전 고정)

프로토타입 단계(W1·W2, `?globe=1`, A안/B안 전환 포함):
1. 손을 뗀 뒤 1.5초 안에 가장 가까운 주제가 |Δ|<1°로 멈춘다. φ를 `data-phi`로 노출해 e2e로 확인.
2. 정면 주제의 카드 scale ≥ 0.95, 글자 실효 크기 ≥ 14px. 데모의 가장 큰 주제 기준으로 카드가 모두 보이거나 무리 안 스크롤로 닿는다. 다른 주제는 scale < 정면, 투명도 < 1.
3. 단위 테스트: 6주제의 β가 10° 이상 간격으로 3군 이상. 화면(φ=0)에서 y 간격 ≥ 24px인 높이 3단 이상.
4. 단위 테스트: |Δ|>90°에서 dx/dφ 부호가 앞면과 반대이고(내용 좌우 반전 없음, 이동 방향만), 투명도 ≤ 0.2.
5. 측정 스크립트(`scripts/perf-globe.mjs`): 200장/15주제 데모, 크롬 CPU 4배 감속, CDP 터치로 3초 끌기, rAF 간격을 3회 재서 중앙값 기준 32ms 넘는 프레임 ≤ 5%. **보드 모드와 쓰기 모드(흐린 배경+자동회전) 둘 다.** 사용자의 실제 안드로이드 폰에서도 1회 끌어 보고 끊김 여부 답.
6. 사용자가 폰에서 A안/B안을 보고 세 질문에 답한다: ① 회전 속도·관성이 적당한가 ② 옆 주제 크기·투명도 ③ 높이 배치. 답이 "아니다"면 상수 조정 1회 후 다시 확인, 그래도 아니면 설계로 돌아간다. 프로토타입에 흐린 배경 위 쓰기 칸 목업을 포함한다.

시험판 2차(D11~D14, `?globe=1`):
2-1. 조망 화면·"전체"·"돌아오기" 버튼이 없다. 첫 화면에서 정면 주제의 메모가 펼쳐져 있다.
2-2. 좌우로 끌면 옆 주제가 정면으로 오는 동안 크기와 펼침이 연속으로 커진다(중간 프레임 캡처에서 펼침 정도가 0과 1 사이인 주제가 있다). 멀어지는 주제는 이름표+점으로 접힌다.
2-3. 멈춘 뒤 정면 주제 이름표의 중심이 화면 중심에서 ±8px 안. 그 주제 메모 카드가 모두 한 화면 안에 보인다(가장 큰 주제 포함, 스크롤 없음).
2-4. 끌기는 좌우만. 손을 놓으면 가장 가까운 주제가 정가운데(±8px)로 멈추고, 그 주제 높이에 맞춰 시선이 위아래로 따라간다. 6주제 데모에서 주제 이름표의 화면 y가 화면 높이의 60% 이상 범위에 퍼져 있다(정면 펼침 제외).
2-4a. 어안: 같은 카드가 화면 중심에 있을 때가 가장자리에 있을 때보다 크다(단위 테스트로 배율 함수 확인).
2-4b. 정면 주제 카드는 생성 시각 순으로 이름표 둘레를 시계방향(12시 방향 시작)으로 놓인다(단위 테스트).
2-5. 큰 데모 측정에서 32ms 넘는 프레임 ≤ 5%. typecheck·lint·test, 깃발 없는 e2e 통과.
2-6. 사용자가 폰에서 다시 확인.

본 구현(W3~W6):
7. 첫 실행 시 쓰기 모드. 데스크톱은 탭 없이 첫 키 입력이 쓰기 칸으로, iOS는 탭 1회로 입력 시작. 백그라운드 5분 뒤 복귀하면 쓰기 모드.
8. 쓰고 Enter → 카드가 목표 주제로 날아가고(필요하면 회전 먼저), 쓰기 칸은 사라져 지구본만 남는다. "새로 쓰기" 버튼 1회로 쓰기 칸이 다시 나온다. 연달아 3개를 저장해도 유실 0.
9. `+` → 녹음, 사진 각각 저장까지 된다. 마이크·카메라 권한 거부 시 안내가 뜨고 앱은 멈추지 않는다.
10. 아래 각각 e2e 1개: 메모 탭 상세, 길게 눌러 다른 주제로 옮기기(가장자리 회전 포함), 주제 이름 바꾸기, 재구성 되돌리기, 동작 줄이기(관성·자동회전 없음).
11. `npm run typecheck`, `lint`, `test`, `test:e2e`(새 선택자로 고친 것) 통과.
12. iOS 홈화면 앱과 안드로이드 홈화면 앱에서 각 1회 확인. 스키마 v3 이전 후 기존 메모 수가 그대로.

| W6 | e2e·스크린샷 갱신 | `tests/e2e/*` | sonnet | §4의 11 |

## 6. 위험

- 주제가 많을 때(20개+) 한 바퀴가 길어져 원하는 주제 찾기가 오히려 느려짐 → 조망(오므리기) + 라벨 탭 이동으로 보완.
- 2D 지도에서는 "가까운 주제 = 관련 주제"를 상하좌우로 표현했지만 원 위에서는 좌우 이웃 둘뿐 → 관련 정보 일부 손실.
- 계속 도는 화면은 멀미·배터리 부담 → 자동 회전은 쓰기 모드 배경에서만, 동작 줄이기 존중.
- 흐림과 회전을 같이 켜면 매 프레임 다시 흐려야 해서 가장 비싸다 → 쓰기 모드는 라벨만 남긴 최저 세부 단계 + 반투명 덮개가 기본, blur는 측정(§4-5) 후 허용될 때만.
- 주제 순서가 매번 다시 계산되면 위치를 못 외운다 → D8 순서 저장.
- 가로 회전·세로 스크롤·오므리기·길게 눌러 끌기·iOS 확대/뒤로가기 제스처가 겹친다 → §3.2 축 고정 판정.
- 키보드가 뜰 때 화면 높이가 바뀌어 지구본이 튄다(안드로이드는 뷰포트 축소, iOS는 화면 밀림) → §3.4.
- 연달아 저장하면 배경이 계속 크게 돌아 멀미 → 회전 합치기(§3.4).
- 데이터 극단값(주제 1~2개, 15개 이상, 한 주제 100장) → §3.2 각도 간격·요약.
- 느낌 위주 요청이라 첫 시안이 의도와 다를 가능성이 큼 → D4 프로토타입 먼저, D9 두 안 비교.
