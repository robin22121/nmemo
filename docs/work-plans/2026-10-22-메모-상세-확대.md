# 메모 상세: 카드가 커지는 메모장(수정·설정)

상태: 확인대기

## 0. 결정

사용자 요청(2026-10-22, 원문 요약):
1. 메모에 수정 기능이 없다.
2. 메모 상세가 아래에서 슬라이드로 올라오는데, 기존 메모 모양이 **커지면서 상단으로 확대**되는 애니메이션이어야 한다.

## 2. 설계

### 2.1 열기·닫기(카드가 커짐)
- 열기: 탭한 카드 `.card`의 화면 사각형(시작)을 재고, 자식 없는 **껍데기**(배경·모서리·그림자만, 주제 색 번짐 D21)를 시작 사각형에 놓은 뒤 `top/left/width/height/border-radius`를 목표(위 = safe-area + 12px, 좌우 12px, 높이 = 보이는 화면 높이 − 위·아래 여백)까지 스프링(`spring.glide`)으로 키운다. 끝나면 껍데기 자리에 실제 패널을 마운트하고 내용이 흐려지며 나타남.
- 패널에 측정값을 속성으로 남김: `data-flip-from`(시작 사각형) — 검증용.
- 원래 카드는 열린 동안 `visibility:hidden`(자리 유지).
- 닫기: (편집 중이면) 먼저 blur → 자판 닫힘(`visualViewport` 높이 복귀 또는 400ms) 대기 → 그때 카드 사각형을 **다시 잰다** → 내용 사라짐 → 껍데기가 카드 자리로 줄어듦 → 카드 다시 보임. 카드가 없으면(삭제·다른 주제로 이동·화면 밖) 껍데기는 제자리에서 흐려지며 사라짐.
- `prefers-reduced-motion`: 커짐 없이 흐려지며 나타남/사라짐.
- 끌어 닫기: 손잡이에서만, 또는 안쪽 스크롤이 맨 위(`scrollTop===0`)이고 편집 중이 아닐 때만 시작.
- 접근성: `role="dialog" aria-modal="true"`, 열 때 닫기 버튼으로 포커스, 닫을 때 카드로 포커스 복귀, Escape로 닫기.

### 2.2 두 안 (E5)
- **A 덮기**: 패널은 불투명 종이색 + 주제 색 은은한 번짐. 뒤 보드는 종이색 덮개(0.55)로 가라앉힘. 글 읽기 가장 편함.
- **B 반투명**: 패널은 주제 색 유리(배경 투명도 0.72 + `backdrop-filter: blur(18px) saturate(1.2)`). 뒤 보드가 흐리게 비쳐 "같은 하늘 안에서 펼쳐진" 느낌. `backdrop-filter`는 **열기 애니메이션이 끝난 뒤에만** 켠다(껍데기는 반투명 색만). 글자 대비 4.5:1 미달이면 글자 쪽 배경만 진하게.
- 스위치: `src/ui/globe/config.ts`에 `SHEET_STYLE` = URL `?sheet=` 값, 기본 `glass`(폰 비교 후 확정하고 스위치 제거).

### 2.3 수정(E2·E3)
- 본문은 연필 표시가 있는 편집 영역(`aria-label="메모 고치기"`). 누르면 `textarea`(자동 높이)로 바뀌고 커서. 위에 "완료". 사진 메모는 사진 아래 설명만 편집.
- 저장: 글이 바뀌었으면 `editMemoText` → `updateMemo({ text, editReanalyze: true, status:'pending', attempts:0 })` + 큐 깨우기.
- `applyResult`: `editReanalyze`면 `topicLocked`처럼 주제를 유지하고, 적용 후 `editReanalyze`만 지운다. **분석한 글이 현재 글과 다르면 결과를 버린다**(분석 요청 때의 글을 결과와 함께 넘겨 비교) — 편집 중 앞선 정돈이 끝나 옛 글 요약을 쓰거나 표시를 지우는 경쟁 방지. 실패(`failed`)로 끝나도 `editReanalyze`는 남는다.

### 2.4 설정(E4·E6)
- 위쪽 줄: 종류 칩(누르면 4개 중 고르기) · 감정 칩(누르면 기본 감정 8개: 기쁨·설렘·평온·담담·걱정·슬픔·화남·지침 — 색은 감정 팔레트) · 날짜 · 닫기.
- 고르면 `kindLocked`/`emotionLocked = true`. `applyResult`는 잠긴 항목을 덮어쓰지 않음.
- 할 일: 완료 체크. 주제: "주제 바꾸기"(주제 색 알약 목록)·새 주제. 맨 아래 삭제(확인).

### 2.5 자판 흔들림 방지(E7)
- 열려 있는 동안 `html, body { overflow: hidden; height: 100% }`, `overscroll-behavior: none` → 문서 스크롤 자체가 없다.
- `visualViewport`의 `resize`·`scroll` 둘 다에서 rAF 1회로 패널에 직접 적용: `transform: translateY(visualViewport.offsetTop px)`, `height = visualViewport.height − 위 여백 − 12px`. transition 없음. → iOS가 visual viewport를 pan해도 패널은 보이는 화면 위쪽에 붙어 있다.
- 편집 영역은 패널 위쪽에 두어(패널이 위에 붙으므로) 자판 위에 항상 보이게 → iOS가 pan할 이유를 줄임. 긴 글은 패널 안쪽만 스크롤해 커서 줄을 보이게.
- viewport meta는 바꾸지 않음(`interactive-widget`은 iOS 미지원).

## 4. 종료 조건 (실행 전 고정)
1. 글 수정 → 저장 → 새로고침 후에도 바뀐 글(e2e). 글 메모를 빈 글로 저장하면 원래 글 유지, 사진 메모는 빈 설명 저장 가능(e2e).
2. 단위 테스트 4건: `applyResult`에 결과 topic≠현재 topic, kind≠현재 kind를 넣어도 `editReanalyze`·`kindLocked`·`emotionLocked` 상태면 topic·kind·emotion 불변 / 적용 후 `editReanalyze`만 false / 분석한 글≠현재 글이면 결과 폐기(아무것도 안 바뀜) / 실패해도 `editReanalyze` 유지.
3. 열기: 패널 `data-flip-from`과 탭 전 카드 사각형 차 ±6px, 애니메이션 끝난 뒤 패널 사각형 = {top: safe-area+12, left: 12, width: 화면폭−24} ±2px. 닫기 끝난 뒤 패널이 DOM에서 사라지고 카드가 다시 보임. reduced-motion에서도 열고 닫힘(e2e, Chromium 390×844).
4. 캡처 4장: 두 안 × (읽기·편집 중). 사용자가 기본값을 고르면 E5를 "확정"으로 바꾼다.
5. 종류·감정·완료·주제 변경(새 주제 만들기 포함)이 저장되고 새로고침 후 유지(e2e).
6. **실제 iPhone 사파리·카카오톡 각각**: 자판 열기 전 / 열린 뒤 / 닫힌 뒤 캡처 3장에서 패널 윗변 y가 같고(0px 차), 편집 중 커서 줄이 자판에 가리지 않고, 깜빡임 없음 — 사용자 폰 확인. 확인 전에는 완료라 하지 않는다.
7. 자판이 열린 채 닫기를 눌러도 카드 자리로 정확히 줄어듦(e2e: 편집 중 닫기 → 닫힌 뒤 카드 보임) + 폰 확인 1회.
8. E8: `src/ui/sheet.css`·메모장 CSS에 `#fff`/`#ffffff`·시스템 파란색(`#007aff`, `blue`)·`border-radius: 0` 없음(grep) + 사용자 승인 1회.
9. build·lint·unit·e2e 통과.

## 5. 위험
- iOS visual viewport pan과 `resize`가 자판 애니메이션 끝(~250ms) 뒤에 오는 문제 → 그 사이 패널이 잠깐 밀릴 수 있음. `scroll` 이벤트로 즉시 따라가게 하고 폰에서 확인(종료 조건 6). 카카오톡 웹뷰는 따로 확인.
- `backdrop-filter`(B안) × 크기 애니메이션: Safari가 매 프레임 다시 그려 구형 iPhone에서 버벅임, 간혹 3D 자식을 흐리게 못 함 → 열기 끝난 뒤에만 켬.
- 닫기 목표 변동: 열린 동안 주제 이동·삭제로 카드가 사라지거나 옮겨짐 → 닫기 직전 재측정, 없으면 흐려지며 사라짐.
